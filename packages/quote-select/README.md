# dsh-plugin-quote-select

选中对话里的任意一段文字，浮出一个小药丸：**引用** 把它加进输入框，**评论** 先写一句话再加进去。已引用的段落在对话里保持高亮，输入框上方多出一条引用带，发送前评论都还能改。

```
用户选中助手回复里的一句话
        ↓
   ❝ 引用 │ 💬 评论      ← 浮在选区上方
        ↓
输入框里多出一行 `> 引用1（助手）：……`，光标回到正文末尾
```

## 引用存在草稿里，不在插件状态里

harness 只给插件一条公开的草稿写入路径（`inputActions.setDraft`），发送时**没有**任何钩子。所以一份平行的引用列表没有办法把自己塞进发出去的那条消息里 —— 引用只能存在草稿文本本身。

格式是 Markdown 引用块，压在草稿最前面：

```
> 引用1（助手）：被选中的那段话
> 评论1：用户写的评论
> 引用2（用户）：另一段

用户自己写的正文
```

这条选择顺带买到了几样东西：发送、按会话隔离、草稿持久化全部沿用现成机制，一行额外接线都不需要；而且输入框里读到的，逐字就是模型收到的。

代价是**引用文本会占据输入框的可见空间**，以及正文不再从第 0 个字符开始 —— 开头的 `/斜杠命令` 会因此失效（先发引用、再单独发命令即可）。

关键不变量：引用带每敲一个字符就把整段前缀重新拼一次，所以 `compose(parse(draft))` 必须逐字返回原草稿。因此[`quote-block.ts`](src/client/quote-block.ts) 里任何**已存储**的值都不做 trim 或空白折叠 —— 归一化只在捕获那一刻发生一次。

三个上限都是**可配置的**（设置 → 插件 → 划词引用），不是常量：一条消息该带多少引用文本，是对该部署模型和上下文预算的判断，不是引用机制本身的性质。

| 上限 | 默认 | 范围 | 到顶时 |
|---|---|---|---|
| 单条引用 | 600 字符 | 50–4000 | 截断并接 `…` |
| 单条评论 | 200 字符 | 20–1000 | 输入框 `maxLength` 拦住 |
| 每条消息 | 8 条引用 | 1–32 | 药丸两个按钮都拒绝 |

范围写在 [`namespace.ts`](src/namespace.ts) 的 `LIMITS` 里，schema 和卡片的输入框共用同一份，所以控件给不出宿主会拒绝的值。没有 settings provider 时用 schema 默认值，插件照常工作。

## 一个插槽，三个界面

全部注册在 `conversation.input.dock` —— 这是唯一同时带着实时草稿和 `inputActions` 的插槽，而两者这个插件都要。药丸和高亮不是 dock 的内容：它们从同一个组件 portal 到 `document.body`、以及通过 Highlight API 画出来，所以三个界面读的是同一份状态，而引用带为空时这个座位不贡献任何布局。

| 界面 | 怎么画的 |
|---|---|
| 选区药丸 | portal 到 `document.body`，测量后再定位（宽度取决于文案，进评论态还会变宽） |
| 段落高亮 | CSS Custom Highlight API，活的 `Range`，不碰 DOM。消息重渲染时 Range 自然塌缩、停止绘制 |
| 编号气泡 | 同一批 `Range` 的最后一个 client rect，滚动/缩放时按 rAF 重算；裁在转录可见区内，同一行上两个气泡会互相让位 |
| 引用带 | dock 里的普通行，几何值抄自 `TodoPanel.module.css`，与待办／队列／目标三张卡对齐 |

高亮和气泡说的是两件事，所以两个都留着：**高亮划出范围**（引到哪儿为止），**气泡标出身份**（这是第几条）。气泡的数字和配色与引用带里的序号一致，两处指的是同一个东西。只有高亮时视觉上太轻，容易在长回复里找不着。

高亮用的活 `Range` 存不进草稿（Range 不是文本），所以它们按位置与解析出的引用一一对应，由每个改动维护；数量对不上（用户手改了草稿里的引用行）就整体丢弃 —— 高亮丢掉好过高亮错位。浏览器不支持 Highlight API 时高亮自动关闭，其余照常。

## 依赖的 DOM

四个 harness 有意渲染的 `data-` 属性，集中在 [`chat-dom.ts`](src/client/chat-dom.ts)（harness 的类名按构建哈希，从仓库外够不着）：

- `[data-chat-flow-kind]` —— 选区是否落在消息里，以及作者是谁（`user` / `assistant-step` / `turn-tail`）
- `[data-input-scroll] textarea` —— 引用加入后把焦点和光标还给输入框

跨消息拖选只认起点所在的那条，整段作为一条引用，而不是直接拒绝。
